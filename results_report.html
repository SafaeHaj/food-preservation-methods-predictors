Executive summary — v4 vs. v3 vs. v1, on the identical 319-case test set

  • V4 fixed the one specific problem flagged in the v3 report. A_STRICT_REAL (n=27, the tier singled out for R²): R²=-1.42 (v3) → R²=0.34 (v4, XGBoost), or R²=0.49 with LightGBM (v4's new default best model) — essentially back to v1's original quality. The 2 feta rows that broke this tier in v3 are now predicted accurately again.
  • But v4 is not a net improvement — it traded one problem for two others. Pooled R² across all 319 rows fell: 0.445 (v3) → 0.107 (v4).
  • Semi-hard cheese collapsed: R² 0.558 (v3, genuinely good) → 0.018 (v4), bias +16.3d → +68.1d. Root-caused below (§8.4) to the v4 training labels for processed cheese, kashar, and gouda being substantially inflated versus v3.
  • C_SAFETY_EVENT_REAL got substantially worse: R² -0.95 (v3) → -4.47 (v4) — same root cause, since most of these rows are processed-cheese pathogen-challenge cases.
  • Hard cheese continued improving (R² -2.93 → -0.52), and lower-bound compliance held roughly flat (54% → 55%).

1. Methodology

319 real-condition cases traced to 34 distinct published papers (source_rule_id holds the actual DOI/PubMed link for each). data_origin = external_literature_real_condition and training_weight = 0 for every row — entirely disjoint from the training set, never used in fitting. Each row's quality_flag prefix is a confidence/comparison-semantics tier:

TiernMeaning
A_STRICT_REAL27Exact reported value from the paper. Highest confidence.
A_RANGE_REAL4Paper reported a range rather than a single value.
B_OVERALL_REAL23Overall / nominal shelf-life claim stated in the paper.
B_LOWER_BOUND_REAL54Paper reports “no spoilage by day X” — true value is at least X.
C_STUDY_HORIZON_REAL159Value is bounded by how long the study ran (looser lower bound).
C_SAFETY_EVENT_REAL52Value tied to a specific pathogen/safety endpoint, not general spoilage.

All 4 live production models (Random Forest, LightGBM, XGBoost, Explainable Boosting Machine) were evaluated identically via ModelService.predict_one() — the exact same code path the deployed app uses, with zero retraining. Metrics: MAE (mean absolute error), RMSE, R² (coefficient of determination against the reported/imputed true value), MAPE, bias (mean signed error — positive means overprediction), and median absolute error (robust to outliers).

This report compares three model generations against the identical, unmodified 319-row file: v1 (original training data, backed up under model_versions/v1_restored_baseline_2026-08-18_141539/), v3 (broad recalibration of hard/semi-hard labels, 48,240 rows, backed up under model_versions/v3_recalibrated_2026-08-19_124027/), and v4 (current live models, a more targeted recalibration on 35,650 rows — ~26,050 rows retained from the original v1-era base plus ~9,600 rows newly added/recalibrated under synthetic_independent_literature_calibrated_v4 / synthetic_recalibrated_v4). All single-version sections below (3 onward) reflect v4, the current live app; §2 puts all three side by side. XGBoost is used as the comparison model throughout for architecture-controlled consistency across versions, even though v4's own best-by-validation model is now LightGBM (noted where relevant).

Same check as in the v1 and v3 reports: if the model were simply being asked to extrapolate past its training range, restricting to in-range rows only should improve results.

Same result as before: in-range performs worse, not better (R² 0.12 in-range vs -28.58 out-of-range). Extrapolation is still not the explanation for v4's weak spots — both the A_STRICT_REAL fix and the new semi-hard regression are in-distribution calibration effects.

8.2 — Hard cheese: the v1→v3→v4 label and prediction arc

Parmigiano Reggiano. Real case: 597 days already aged, paper reports 90 days. Matching synthetic training rows (hard category, ripening within ±30% of the real case, controls only) — median labeled shelf life: v1 242.7d (n=95, inflation 2.70×) → v3 121.3d (n=311, inflation 1.35×) → v4 115.6d (n=205, inflation 1.28×). The label has kept moving toward the real value across all three versions.
The model's live output has partly caught up. Mean XGBoost prediction across the Parmigiano test rows: v3 206.4d → v4 123.2d — still well above the real value (90d), but the gap between label and live output that the v3 report flagged has narrowed, consistent with hard cheese's continued (if incomplete) improvement in §2 and §6.

Reading: hard cheese is the one category recalibrated consistently across both v3 and v4, and it shows a consistent, monotonic improvement in both the label and the live prediction. It is the model of what "targeted recalibration done right" looks like — contrast with §8.4.

9. Lower-bound compliance, v1 / v3 / v4

For tiers where the reported value is a floor (paper states "no spoilage observed by day X" — the true shelf life is at least X), a correct model should predict at or above that floor.

55% of 265 lower-bound-semantics predictions (XGBoost, v4) meet or exceed the reported floor (v1: 57%, v3: 54%). 120 rows under-predict a duration the literature has already demonstrated is safely exceeded. Materially unchanged across all three versions — neither recalibration targeted bound semantics specifically.

13. Recommendations

What v4 already achieved, and shouldn't be undone: the A_STRICT_REAL/feta fix and hard cheese's continued improvement are both real and should be preserved. The problem is not that v4 recalibrated — it's that the recalibration of semi-hard matrices (processed cheese, kashar, gouda) moved the label in the wrong direction while other matrices moved correctly.

Recommended, in order of expected payoff:

  1. Re-examine the specific v4 label-generation step for processed cheese, kashar, and gouda — these three matrices' labels moved substantially up from v3 (§8.4), while the overall recalibration intent (based on the v3→v4 fixes seen elsewhere) appears to have been to bring hard/A_STRICT_REAL matrices down toward real values. This looks like a sign-flipped or mis-scoped adjustment for this specific subset, not a fundamental data problem.
  2. Separately, address the pathogen-challenge blind spot directly: add indicator_type-aware short-shelf-life training examples for processed cheese (and any other matrix with C_SAFETY_EVENT_REAL coverage) so the model can learn that a deliberate high-inoculum challenge study produces a very different outcome than a background-safety control at the same temperature. This is a data-coverage gap, not a calibration-scale problem, and predates v4.
  3. Continue the Parmigiano-style approach for hard cheese: the label-to-live-output gap is narrowing but not closed; keep tracking it explicitly in the next iteration rather than assuming the label fix alone will finish the job.
  4. Soft cheese continues to need no intervention (R² = 0.34).
  5. Given the whack-a-mole pattern across v3→v4 (fixing hard/A_STRICT_REAL while breaking semi-hard), any future recalibration pass should re-run this full 319-case evaluation before declaring success, specifically checking every category and tier this report tracks, not just the one that motivated the change.
