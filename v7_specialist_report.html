Executive summary

  • All three general_shelf_life specialists are excellent: test R² ranges 0.920–0.971.
  • All three safety_endpoint specialists are degraded, in a pattern that tracks almost exactly with how many of their target values are right-censored ("at least N days") rather than exact — see §5.
  • Hard / Safety endpoint has effectively collapsed to predicting the training mean (test R²=-0.011) — confirmed directly, not inferred (§6).
  • A real preprocessing bug (% w/w concentration unit, 17,662 V7 rows) was found and fixed during verification, not a data change (§8).
  • No physical-form combination in V7 can reach "Strong" support — a real, honestly-reported regression vs V6’s data (§9).
  • No correction multiplier, offset, clipping, or manual calibration was added anywhere in this work (§10).

1. What changed in V7

The user replaced the raw specialist training data with three "corrected" V7 files. Verified directly against the data (not assumed): V7 adds 13 columns beyond V6’s 62, most notably genuine challenge-context fields (is_challenge_test, initial_inoculum_log_cfu_g, growth_support) and a target-censoring flag (target_is_lower_bound). Row counts are lower than V6 (V7 totals 34,000 rows across the three category files vs V6’s ~35,650), and vocabulary is narrower (soft: 19 food_matrix values, semi-hard: 11, hard: 6), consistent with a more literature-anchored, "corrected" scope.

2. Architecture & constraints

Same six-specialist architecture as V6: one model family per (cheese_category, model_task), each a Random Forest / LightGBM / XGBoost / EBM ensemble, routed automatically. New context-scoped train/validation/test splits were built fresh from the V7 data (leakage-safe, grouped by context_id, seed=42). The production model for each specialist is selected purely by validation RMSE. Saved under a new artifacts_v7/ directory; artifacts_v6/ is untouched (confirmed via unchanged file modification times). No dataset regeneration, rebalancing, relabeling, or augmentation was performed, and no correction multiplier, offset, clipping, or manual calibration was added to any prediction — confirmed by grep across every file touched in this work, both before and after.

5. The censored-target finding

V7 introduces target_is_lower_bound: a flag on rows where the literature source reports "no spoilage/no growth by day N" rather than an exact shelf-life value — the true value could be materially higher than N. Standard regression treats every target as exact. The proportion of censored targets rises sharply from soft → semi-hard → hard safety specialists, and test R² falls in the same order:

Specialist%LB train%LB validation%LB testTest R²
Soft / General shelf life 0%0%0% 0.971
Soft / Safety endpoint 73%73%69% 0.594
Semi-hard / General shelf life 0%0%0% 0.920
Semi-hard / Safety endpoint 95%94%93% 0.317
Hard / General shelf life 0%0%0% 0.932
Hard / Safety endpoint 100%100%100% -0.011
This is a genuine data-learnability problem, not a preprocessing or wiring bug: a model trained to hit an exact-value loss on a target that is secretly "at least N" for most rows cannot help but be biased/underdetermined. It was not fixed with a correction here, per instruction — it is reported so the forthcoming independent V7 test set (or a future censoring-aware retrain, e.g. Tobit/survival-style loss) can address it deliberately.

8. Bug found and fixed during verification: % w/w concentration unit

All three V7 files use % w/w as a raw primary_concentration_unit spelling (17,662 rows total). concentration_units.py’s conversion table had "%" and "wt %" mapping to canonical % w/w, but no entry for the raw spelling % w/w itself — to_canonical() would have raised UnrecognizedConcentrationUnit on every one of those rows at prediction time. Verified empirically (module’s own methodology): the canonical/raw value ratio for these rows is exactly 1.0 with zero variance across all 17,662 rows. Fixed by adding the verified self-mapped entry and extending the module’s --verify check to cover V7 as well as V6. This is a preprocessing correctness fix, not a change to any training or test data.

9. Physical-form support regression (data property, reported not fixed)

In V7, physical_form_observed is 0 for every row in all three category files, and physical_form_source is always "literature_supported_typical_form" (never "explicit_matrix_name", which some V6 rows had). Under the existing, unmodified support-level bands, this means no V7 prediction can reach "Strong" physical-form support — the best achievable is "Moderate" (confidence ≥ 0.85). This is a real characteristic of the V7 data, surfaced honestly through the existing support-assessment machinery, not a bug and not something this pass changed the bands to hide.

11. Recommendations

  1. Do not attempt to "fix" the safety specialists’ R² with a correction factor — the root cause is target censoring, and a correction would hide rather than address it.
  2. When the independent V7 external test set is built, consider excluding or separately reporting on rows whose true value is itself a lower bound, since a specialist trained on censored data cannot be fairly scored against an exact-value ground truth using standard R²/MAE.
  3. If safety-endpoint accuracy needs to improve, the highest-leverage next step is a censoring-aware training objective (e.g. Tobit regression or a survival/hazard formulation) for the three safety specialists specifically — not more data volume or a different off-the-shelf algorithm, since all four algorithms show the same degradation pattern in §4.
  4. General-shelf-life specialists need no further work — all three are strong and show only modest train−validation gaps.
  5. Before any live promotion decision, re-run this evaluation against the user’s forthcoming independent V7 external test set, not just V7’s own held-out split.
