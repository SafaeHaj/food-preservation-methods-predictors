1. Test set

21 cases across 6 independent papers, all with exact ("point", zero-censoring) targets and direct_model_compatible=yes. All rows are general_shelf_life (no safety-endpoint cases in this file). Category split: soft n=9, semi-hard n=7, hard n=5.

2. Methodology — what was and wasn't normalized

Evaluation uses the exact production code path: SpecialistRegistry.resolve() / assess_prediction_support() / ModelService.predict_one() — the same functions /api/v6/predict calls, not a separate reimplementation. Two, and only two, normalizations were applied, both pure notation (verified, not guessed):

  • cheese_category spelling: "semi-hard" → "semi_hard". This is a routing key only — cheese_category is not even a model feature.
  • Concentration units run through the same to_canonical() a live request would use; where the file’s unit isn’t in the verified table (%_coating_solution, 2 rows), the conversion is left unavailable (None), not guessed.

Nothing else was remapped. food_matrix, physical_form, packaging_type, and indicator_type values that don’t match V7’s training vocabulary are passed through as-is and flagged by the existing support-assessment machinery, exactly as a real live prediction would be.

5. Deep dive: hard cheese on real data

All 5 hard-cheese rows come from one paper (Provolone, aged 6 months, five packaging/CO₂ conditions). True values span 100–280d; predictions cluster at 59.5–64.6d — the model is nearly insensitive to what actually distinguishes these five real cases. MAE=111.9d, bias=-111.9d (systematic underprediction), R²=-3.112.

This mirrors a generalization weakness that has recurred across multiple model generations in this project’s history for long-aged hard cheese — the V7 retrain and architecture change have not resolved it. It is reported as-is; no correction was applied.

6. Bug found and fixed while building this evaluation

ModelService.assess_support() compared every numeric field’s raw value against its training range without first checking for NaN (as opposed to None) — the natural result of pandas.read_csv on an empty cell, which several rows in this external file have (e.g. missing matrix_ph). A NaN always fails a range comparison, so it was being reported as a false "value=nan is outside the training range" extrapolation instead of being treated as missing data; the same applied to categorical NaNs being reported as an unseen category "value='nan'". Fixed with a shared missing-value check used in both the categorical and numeric loops, verified directly, and re-confirmed the full 23-case pytest suite (test_v6_specialist_routing.py) still passes since this is shared V6/V7 infrastructure.

7. Recommendations

  1. Build (or request) a version of this external file using V7’s own trained vocabulary for food_matrix/physical_form/packaging_type/indicator_type, so accuracy can be assessed independent of vocabulary coverage.
  2. Do not remap or fuzzy-match the current file’s vocabulary retroactively to make the score look better — a wrong mapping would be worse than an honest "unsupported" flag.
